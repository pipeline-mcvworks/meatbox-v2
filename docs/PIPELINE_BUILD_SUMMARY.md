### Goal

Build a phone-first music creation app that lets users record beats, rhythms, beatboxing, vocal percussion, taps, clicks, and other mouth-made sounds, then cleans them up into editable beat patterns on a music timeline.

The app should feel fun, visual, and immediate, but it should also be capable of producing serious beat ideas that can later be exported and used in real music workflows.

Plain English version:

> I want to open the app, make a beat with my mouth, have the app clean it up, map the sounds to drum lanes like kick/snare/hat, snap the timing to a grid, and let me edit/play/export the result.

### Product Positioning

MouthBeat Machine is a playful mobile beat machine / vocal MPC / rhythm visualizer.

It is not meant to be a full DAW in version 1.

It is not meant to be only a toy either.

The core identity should be:

> Fun to record with. Serious enough to make usable beats.

### Target Users

- People who can imagine beats but do not know how to produce them in a DAW
- Musicians who want to capture quick rhythm ideas
- Beatboxers who want to convert performances into structured drum patterns
- Casual creators who want a fun visual music tool
- Producers who want a fast mobile sketchpad
- Content creators who want quick loops for short-form videos

### Core MVP Flow

1. User opens the app.
2. User taps Record.
3. App gives a short countdown.
4. User makes mouth beat sounds into the phone microphone.
5. App shows a live waveform, meter, or reactive visualizer while recording.
6. User stops recording.
7. App analyzes the recording.
8. App detects likely beat hits.
9. App guesses the lane/type for each hit:
   - kick
   - snare
   - hat
   - percussion
   - unknown
10. App snaps detected hits to a musical grid.
11. App creates editable timeline events.
12. User can fix mistakes with touch controls.
13. User can play the cleaned beat using built-in samples.
14. User can change drum kit/sample sounds.
15. User can save the project locally.
16. User can export project data, and later MIDI/WAV.

### Constraints

- Build as a mobile-first app.
- Use React Native.
- Use TypeScript.
- Prefer Expo or Expo Dev Client for the first build.
- Must be usable on phones first, not desktop first.
- MVP should work locally/on-device as much as possible.
- Do not require user accounts for MVP.
- Do not require cloud storage for MVP.
- Do not require backend services for MVP.
- Do not start with complex machine learning.
- Do not build a full DAW in version 1.
- Keep audio logic separate from UI logic.
- Keep project data serializable as JSON.
- Keep the audio engine behind interfaces so a native iOS/Android audio engine can be added later.
- Initial classification can use heuristics instead of trained AI.
- Manual correction must be fast because automatic detection/classification will not be perfect.

### Audio Pipeline

#### Step 1 — Capture Audio

The user records audio through the phone microphone.

MVP requirements:

- Ask for microphone permission.
- Record locally.
- Save recording reference in project state.
- Show recording duration.
- Limit max recording length.

Recommended first max recording length:

- 15 to 30 seconds

#### Step 2 — Generate Waveform

After recording, generate a lightweight waveform representation.

Store waveform as an array of normalized peak values.

Purpose:

- Display waveform quickly
- Show detected hits visually
- Avoid needing to fully decode/render the audio every time

#### Step 3 — Preprocess Audio

Prepare the recording for analysis.

Basic MVP preprocessing:

- Convert to mono if needed
- Normalize volume
- Apply a simple noise gate
- Split into short analysis windows

#### Step 4 — Detect Hits / Onsets

Detect likely beat hit moments.

MVP approach:

- Use amplitude/envelope peak detection
- Look for sudden energy increases
- Ignore peaks too close together
- Store timestamp, energy, and confidence

Each detected hit should include:

```ts
interface DetectedHit {
  id: string;
  timeSeconds: number;
  energy: number;
  confidence: number;
}
```

#### Step 5 — Classify Hits

Classify each hit into a likely lane.

MVP heuristic approach:

- Kick-like: lower frequency/plosive energy, sounds like “boom,” “buh,” “puh”
- Snare-like: noisy mid/high energy, sounds like “kah,” “tah,” “psh”
- Hat-like: short high-frequency energy, sounds like “ts,” “tss,” “ch”
- Perc-like: other short transient sounds
- Unknown: unclear sounds

Important:
Classification will be imperfect. The UI must make it easy to correct.

#### Step 6 — Quantize Timing

Snap events to a music grid.

MVP settings:

- BPM
- Grid size: default 1/16 note
- Quantize strength: 0–100%
- Swing: optional but desirable
- Humanize: later

Store both:

- original timestamp
- quantized timestamp/start beat

#### Step 7 — Create Timeline Events

Convert detected/classified hits into editable timeline events.

Each event should have:

- lane
- startBeat
- originalTimeSeconds
- quantizedTimeSeconds
- velocity
- confidence
- selected sample

#### Step 8 — Playback

Use sample-based playback.

MVP playback:

- Built-in drum samples
- Kick/snare/hat/perc lanes
- Play/stop/loop
- Lane mute/solo
- Lane volume

Important:
Do not depend on React render timing for playback.

#### Step 9 — Export

MVP:

- Project JSON export

Later:

- MIDI export
- WAV export

### Risks

#### Detection Quality

Mouth sounds vary widely. Automatic classification will be wrong sometimes.

Mitigation:

- Make correction fast.
- Show confidence.
- Support unknown lane.
- Let users re-run detection with sensitivity changes.
- Add guided recording later.

#### Mobile Audio Complexity

React Native audio can become limited for serious timing and rendering.

Mitigation:

- Start with simple recording/playback.
- Keep audio behind interfaces.
- Plan native engine later.

#### Timeline Editing on Small Screens

Precise editing can be hard on phones.

Mitigation:

- Use large event blocks.
- Support pinch zoom.
- Support snap-to-grid.
- Use bottom sheets for event editing.
- Avoid tiny controls.

#### Scope Creep

This can easily become a full DAW.

Mitigation:

- Focus v1 on mouth beat to drum timeline.
- Save melody/humming for later.
- Save cloud/social for later.
